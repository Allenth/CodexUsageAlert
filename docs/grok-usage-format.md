# Grok Bot 本地用量数据

应用不会调用 Grok Bot 的私有接口，也不会收集 Grok 的密码或会话凭据。Grok Bot 的用量由你或你信任的本地工具写入以下文件：

```text
~/Library/Application Support/CodexUsageAlert/grok-usage.json
```

文件采用 UTF-8 JSON，示例（日期仅作格式说明，请填入实际时间）：

```json
{
  "service": "grok-bot",
  "usedPercent": 18,
  "resetAt": "2026-11-11T00:00:00+08:00",
  "plan": "你的套餐名称",
  "tasksToday": 2,
  "tasksPeriod": 12,
  "updatedAt": "2026-11-04T12:00:00+08:00"
}
```

| 字段 | 类型与含义 |
| --- | --- |
| `service` | 必须为 `grok-bot` |
| `usedPercent` | 本周期已用百分比，0–100 的有限数值，允许小数 |
| `resetAt` | 实际周期重置时间，ISO8601 日期，包含时区 |
| `plan` | 套餐说明字符串，不知道时可用空字符串 |
| `tasksToday` | 当日任务或消息次数，非负整数，由写入方按本机日期统计 |
| `tasksPeriod` | 本周期任务或消息次数，非负整数 |
| `updatedAt` | 这份数据实际更新的时间，ISO8601 日期，包含时区 |

所有字段均为必填；日期支持 `Z` 或时区偏移，以及带毫秒的格式。未知的额外字段会被忽略。应用不会根据百分比推测任务数。

应用启动、手动刷新和每隔 60 秒会重新读取文件；该检查独立于口袋的刷新频率。文件缺失显示“未接入”，`updatedAt` 距现在超过 24 小时显示“数据过期”。JSON 损坏、字段缺失、数值越界、负计数或更新时间超前超过 5 分钟会显示“数据无效”，不会导致应用退出。文件上限为 1 MiB。过期、无效、缺失或已关闭的服务不参与菜单栏百分比和预警计算。

写入程序应先写同目录临时文件，再原子替换目标文件，避免应用读到半份 JSON。`updatedAt` 应随真实数据更新，不能仅刷新时间以掩盖旧数据。

## 手动备用入口

在应用设置中填写 Grok Bot 已用百分比与重置时间并保存。应用会以原子写入的方式更新同一 JSON 文件，并把 `updatedAt` 设为当前时间。已有套餐和计数会保留；首次填写时套餐为“手动录入”，计数为 0。手动入口不自动获取任务次数；要提供准确的次数，请更新 JSON。

手动填写同样会在 24 小时后过期。外部写入程序下一次更新会替换手动数据，因此请避免多个程序同时写入。监控开关仅控制应用的读取和提醒，不会删除文件。

## 每日分级通知

口袋与 Grok Bot 各自以本机当地日期保存基线和通知记录。当天第一次有效观测建立基线，“今日增加”是随后观测到的额度百分点增量，并非服务端精确的整日账单。当天首次启动前的消费、数据未更新期间的消费无法完整还原。

达到 5、10、15、20 个百分点时触发对应等级，每个服务的每个阈值在同一天最多提醒一次。一次更新跨过多个阈值时只发送最高等级通知，跨过的阈值都记为已提醒。记录会跨应用重启保留；旧版口袋的基线和当天已提醒阈值会迁移。

发现周期重置时间变化或百分比下降时重新建立基线，但不清除当天已经提醒过的阈值，避免周期重置或手动纠正造成重复提醒。新的当地日期会重新建立基线，并重置当天的通知记录。提醒需要 macOS 通知权限；系统专注模式或通知设置仍可能影响实际展示。
