# 版本号与更新记录规则

## 编号来源

版本号和 Build 以当前分支可达的 Git 提交总数为唯一计数来源。一条正式提交代表一次可追踪的产品修改。

- `CFBundleVersion`：直接使用提交总数，从 `1` 开始持续累加。
- `CFBundleShortVersionString`：把提交总数按十进制拆成三段，从最后一位开始累加。
- 第一段不限制位数。

示例：

| 提交总数 | 版本号 | Build |
| ---: | --- | ---: |
| 1 | 0.0.1 | 1 |
| 9 | 0.0.9 | 9 |
| 10 | 0.1.0 | 10 |
| 20 | 0.2.0 | 20 |
| 21 | 0.2.1 | 21 |
| 99 | 0.9.9 | 99 |
| 100 | 1.0.0 | 100 |
| 1000 | 10.0.0 | 1000 |

换算公式：

```text
major = build / 100
minor = (build / 10) % 10
patch = build % 10
```

## 自动同步

`scripts/sync_version.sh` 会在构建沙盒版或正常安装版之前运行：

1. 读取当前 Git 提交总数。
2. 如果存在尚未提交的修改，则预览为下一次提交的编号。
3. 同步写入 `Resources/Info.plist`。

例如当前有 20 次提交并正在开发下一次修改，构建出的测试 App 会显示 `V0.2.1（build 21）`；修改正式提交后，仓库提交总数也变为 21，编号保持一致。

## 应用内更新记录

设置页底部显示当前版本，并提供“查看更新记录”入口。更新记录遵循以下格式：

```text
V0.2.1（build 21）
1. 更新内容
2. 更新内容
```

最新版本置顶，并保留既有提交对应的主要用户可见变化。每次正式提交前应同步补充本次更新内容。
